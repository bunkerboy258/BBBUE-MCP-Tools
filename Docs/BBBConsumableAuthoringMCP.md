# 角色使用动作与战斗特效制作

`editor.configure_action_montage` 配置明确自有的 UpperBody 蒙太奇。序列必须共享骨架，起止时间和正向速度数组一一对应。`loop_index` 指定真实循环片段，负一为单次动作；使用真实区段无限保持，不在运行时固定槽位增加状态。通知轨道独立配置。原生配置失败时不保存。

`animation.run_pie_input_sequence` 的 schemaVersion 为 2。`held.keys` 接收至多十六个实际数字按键名称，例如 G、F、LeftMouseButton 和 RightMouseButton；逐步骤发送按下与释放边沿，结束和取消时释放全部所属按键。`targetController` 可明确指定任一活动 PIE 世界的本地 PlayerController。`editor.inspect_pie_character_runtime` 的 `actor_path` 与 `editor.invoke_pie_actor_function` 同样支持明确的活动 PIE 世界对象，多端验收不能依赖默认世界索引。

## ControlRig 与动作资产

`configure_sequence_rig` 逐帧求值后使用单值欧拉变换接口并明确 `set_key=True`，随后逐键回读。真实血药使用动作的 710 个键与 2.8 秒烘焙通过，空手快速近战的 568 个键通过。

首次绑定轨道需要跨编辑器更新完成初始化。先以空 keys 建立并保存绑定，在下一个批次写入实际 keys。复制 ControlRig 后必须保存并用 `reload_assets_from_disk` 显式重载新 Rig 和绑定序列，再编译虚拟机与写键；图连线能读取或键回读正确，均不能单独证明烘焙姿势有效。低抛腰部保持已通过实际重载、烘焙和截图核验，不保留中间副本。

姿势截图使用完整 CombinedMesh 或经过验证的预览网格。不要将仅含部分骨骼的服装部件当作完整身体预览。

## Niagara 的真实时间与场景测量

特效预览先由原生 `PrepareSystemForPreview` 等待系统与 GPU 着色器就绪，再推进模拟。SceneCapture 持续建立视图。`ReadPreviewSystemAge` 等待并行模拟完成后读取控制器真实年龄，报告同时记录世界经过时间与模拟年龄；界面回调经过时间只用于超时。最终 112 格效果在目标 0.25 秒与 0.70 秒的截图中，实际模拟年龄分别为 0.280 秒与 0.731 秒。

`editor.record_pie_player_view` 按 PIE 世界时间录制完整场景，截图导出和首次编译耗时不计入效果年龄。真实世界时间 6 秒的场景录制已完成。该录制使用额外 SceneCapture，不能同时作为无截图开销的性能测量。

`editor.spawn_pie_niagara_instances` 在明确 PIE 世界同时生成一至十六个自动回收实例。系统及 GPU 着色器先就绪，返回组件路径和生成世界时间；不保存关卡或资产。测试实际并发数量和实例回收，不能仅以生成请求成功认定效果已完成。

性能验收使用独立渲染测试宿主及浮动 PIE 视口，核对实际视口尺寸、相机、画质、世界时间推进与有效 GPU 计时。`editor.resize_pie_window` 的首次尺寸更新可能跨帧完成，重新回读并定点重试；不可把请求尺寸当作实际尺寸。采样前确认游戏未暂停，等待着色器和首次运行预热。模拟停滞时的窗口帧号或低 GPU 数值不计入结果。

2026-10-17 在 RTX 5070 Laptop 8 GB 上，以实际 1280×720、100% 渲染比例、高画质、光追及 Lumen 进行整个引擎帧采样。基线 GPU 中位数 3.78 ms，单枚 6.08 ms，预热后四枚 12.07 ms、峰值 15.76 ms，烟团展开阶段峰值 14.04 ms。最终网格最大轴 112，压力迭代 4，池预热数量 4；池化实例多轮复用且结束后粒子数为零。测得显存占用 6417 MiB。原 160 格四枚并发约 30 至 33 ms。

这些是有限采样窗口内的编辑器整帧数据，包含场景与宿主成本。基线 Game 线程中位数 17.39 ms，四枚 19.19 ms；首次未预热生成出现最高约 158 ms 的帧间隔。不将这些结果写成整个项目、打包版本或首次运行已稳定达到 60 FPS。

## 精确资产清理与通知恢复

`assets.delete_unreferenced_project_assets` 只清理 `/Game/_Project` 下已保存且无组外引用的包。逐项提交当前 sha256，默认 dry_run；先检查引用、脏包和哈希，再申请精确写入并原生删除，核实磁盘文件消失。不生成备份或兼容包。

`assets.restore_missing_animation_notify_classes` 按精确保留事件名称及每包预期数量恢复缺失通知实例。先 dry_run 核对全部目标，再建立真实通知类实例并保存，保持事件时间与序列化时长，恢复状态通知结束链接，不修改其他有效事件。实际修复 56 个转向动画后，失效旧路径引用者为零，四方向移动、转向和急停回归通过。未创建旧路径包或重定向器。

## 本轮验收范围

65 项 MCP 定向检查通过，覆盖工具契约、清理失败边界、动作时间、ControlRig 写键、截图时钟与 PIE 定时调用。UE 的 12 项战斗及物品回归全部通过，覆盖消耗品、物品区域、生命、救援、投掷物物理、爆炸和近战窗口。双端监听主机与客机实测通过高低抛、长按保持、血药恢复、快速近战、菜单取消以及第三端迟加入；16 个物理对象的测试不等于 16 个联机客户端测试。

同宿主网络验收在 PIE 启动前使用 `traversal.configure_pie_traversal_network` 配置客户端数量，在停止 PIE 前以 `restore=true` 恢复原值。该工具契约允许任意世界状态，函数自己核对配置和恢复时机。
