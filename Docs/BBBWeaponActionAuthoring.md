# 已保存握持基准的专属动作制作

## 2026-10-19 明确指节与机构接触修正

动作条目可配置 `finger_curls`、`finger_phase_frames`：每组提供实际 `hand_l` 或 `hand_r`、掌空间非零 `axis_in_hand` 和明确指节 `angles_degrees`。工作器在当前真实掌姿态下追加同一连续弯曲平面的关节旋转，不搜索参数，不改局部位移、骨长或其它关节。阶段是进入、满权、结束满权、退出四帧，五次权重保证边界平滑。默认仍只输出七根臂及辅助骨；显式指节会加入轨道白名单，原生保存入口同样允许三十根实际指骨，拒绝其它任意骨。

`contact_translation` 仅接受明确的枪组件空间厘米向量及四阶段帧号，按每帧实际枪体变换转入角色组件空间；用于已由真实网格证明的机构原点差异，不代替握持校准。`finger_return_frames` 指定操作结束后的起止帧，从该起帧的实际操作手指形状平滑回到已保存左手握持。腕部继续使用原动作的自然释放路径及既有 `return_frames`；不声称原动作已经接触枪栓，也不为消除手指手势而强行拉直整条腕部轨迹。

真实 Rifle02 最终版本采用原插入兼容的新匣挂接，明确追加下三指中节30度、末节20度薄截面卷曲；原生匹配静态匣体与枪体弹匣的162顶点、140三角面后，对插入阶段施加约1.72724cm平移。实际第36帧最大对应顶点误差约0.0000669cm、角度约0.000182度。曾尝试约90度旋转匣体的版本已被拒绝，未作为最终插入结果。

最终装备51帧、换弹67帧、近战36帧、使用返回251帧全部独立原生回读通过；写入外的局部骨姿态保持，辅助骨配对误差未超过0.001cm/0.02度。换弹最终LS的9个阶段经纯瞬态官方烘焙对照 `differentBones=[]`。实际换弹装匣及回握正反侧几何图均由执行代理打开检查；这是制作自检，不冒充人类运行验收。74项针对性工具检查通过，其中5项覆盖显式指节、零权重、边界和非法范围拒绝。

`Scripts/BBBWeaponActionAuthoring.py` 读取完整原生逐帧姿态和本型号正式握姿制作源，输出明确的绝对局部轨道及控制器关键帧。它不优化握姿，也不搜索接触参数。使用前必须先完成真实结构、方向、双手握持及挂接的视觉检查。

## 输入与写入

分段装填的起始动作可显式指定正有限的 `entry_hold_release_frame`，无论 `kind` 名称为何，都先从已保存静态左手握持平滑释放。未指定的 `reload`、`melee` 继续使用各自 `release_frame`，其它分段不自动重入静态握持；循环可保持原装填轨迹，结束段仍由明确的 `return_frames` 回握。新增必要检查覆盖起始、循环、结束及非法释放帧拒绝，相关动作检查共16项通过。

`hand_attachment_grip_changes` 显式记录每个左手附件的 `reference_attachment_local`、当前 `attachment_local` 和 `phase_frames`。满权腕目标为 `wrist * originalLocal * inverse(currentLocal)`，因此改握后同一个匣体的世界轨迹保持；阶段内使用五次权重混合位置和最短弧旋转，空程零权重不改变原动作。旧新匣分别声明有序、不重叠窗口，正式 Notify、制作 LS 及 `attachments` 必须写成同一个当前 local。刚体变换要求有限厘米位置、单位四元数及单位缩放；禁止伸骨、角度搜索或以旋转匣体规避真实接槽。三项必要刚体验证与既有动作检查共15项通过。

只有真实武器几何和动作姿态证明需要小角度机构修正时，才使用 `contact_transforms` 的 `delta_weapon` 与四阶段帧窗口，完整目标为 `gun * deltaWeapon * inverse(gun) * wrist`。它与 `contact_translation` 互斥，先处理机构接触再处理上述附件改握反补偿；不重叠窗口之间保留身体空间取匣动作。禁止把已脱离弹匣槽的自然旧匣旋转强行归零，数字对槽不能替代自然腕姿与实际几何视觉检查。

同一个已证机构刚体平移可显式声明 `contact_translation.phase_windows`，例如 `[[4,10,10,14],[29,36,36,40]]`，分别在取旧匣和插新匣时作用。它与单个 `phase_frames` 二选一；每个窗口仍采用原五次进入与退出，窗口必须有序、互不重叠，取并集权重而不累加同一平移。两个接触窗口之间权重严格为零，保留原身体空间取匣路径，避免把局部插匣校正扩到整个空程而使短臂目标不可达。两项新增防错检查与既有动作测试共12项通过。

- 外部 Python 必须安装 NumPy。输入包括本枪角色/武器真实采样、原挂接、已保存握姿 recipe、每个动作的完整源姿态和明确阶段。
- 武器接触部分采用完整刚体挂接变换，包含旋转；取匣等离开武器的区段由 `free_hand_frames` 保留身体空间轨迹。装备取枪阶段单独设置 `mount_frames`，不得把整段手都固定在枪上。
- `release_frame` 和 `return_frames` 控制腕部衔接，五次权重两端速度与加速度为零。锁骨补偿平滑分布，不改变骨长或缩放。
- 只输出 `clavicle_l / upperarm_l / lowerarm_l / hand_l / ik_hand_l / ik_hand_r / ik_hand_gun` 七根局部轨道。先更新辅助骨父节点再更新其子节点，避免重复继承枪骨旋转。
- 正式输出放在本型号 `Source/Animation/*.json.source`。其中的 `weapon`、`grip_fingerprint`、源动画、目标动画和制作序列必须明确；同一份输出重复写入的是绝对轨道，不累计偏移。

原生入口 `grip.apply_action_recipe(weapon_root, recipe_path, action_index, dry_run=true)` 限定本型号、正式制作源和允许骨骼；预检真实控制器及全部关键帧，再原生替换轨道、更新 Rig/LS 与已有武器挂接。新目标从明确源复制；现有目标只改七根骨骼。工具不替调用者选择机构、改变通知或编造人工验收。

## 独立验证

写入后重新调用 `animation.probe_animation_component_poses` 获取正式资产每一个实际关键帧。工作器的 `--verify <实际原生报告>` 检查辅助骨与手骨、七根写入轨道、其余局部骨骼及完整回握阶段目标。原生关键帧保存、数字验证与视觉检查分开记录。

曲线与蒙太奇仍使用已有原生入口分别保存并回读。`DisableLeftHandPoseOverride` / `DisableRightHandPoseOverride`、左手 IK、Aim IK 各自控制对应职责；按实际动作片段和时长设置，不能把另一型号帧号直接当作本枪时序。

静态双手和动作中段的正式原生网格可交给 `BBBGripVisualReview.py`。动作原始手指不包含运行时握姿层混合；武器弹匣隐藏和另挂手部的弹匣也不等于武器源动画里的可见网格。报告必须注明这类边界，不能把图生成成功或极小轨道误差当成自然握持通过。

## 2026-10-18/19 实际验证

- 四项工作器回归通过：旋转及平移接触转换、嵌套辅助骨父子顺序、跨正负 179 度的最短弧、五次权重端点。
- UE5.8 隐藏 Balanced 宿主真实执行 Rifle02 四条动作，共 405 帧；正式逐帧独立回读通过。辅助骨最大位置误差约 0.000061 cm、旋转约 0.000114 度，其余未改局部骨骼误差约浮点精度。
- Rifle02 四条 LS 均经官方序列烘焙器独立对照实际阶段，未发现超过 0.01 cm 或 0.1 度的骨骼差异。旧审计入口产生的临时烘焙包已删除；现审计仅操作纯瞬态副本，不保存正式包。UE动画控制器仍持有的瞬态对象如实记录为 `pending_host_shutdown`，由后续正常宿主退出结束生命周期，不伪造即时GC成功。
- 握姿人工确认仅适用于用户已明确通过的 Rifle01、Rifle02 静态版本。其余动作视觉和最终用户运行观感不得被上述数字验证冒充。

## 共享手部辅助骨同步与静态独立验收

`synchronize_hand_helpers` 的唯一实现位于 `BBBGripAuthoring.py`，静态 solve 与 `BBBWeaponActionAuthoring.py` 均直接调用；动作工作器保留同名导入供现有调用者使用，没有复制实现。按实际骨架父骨在前的顺序先同步 `ik_hand_gun`，再同步其左右手辅助子骨，避免更新父骨后重复带偏子骨。

静态 audit 独立读取实际原生组件变换，检查实际存在的 `ik_hand_gun -> hand_r`、`ik_hand_r -> hand_r`、`ik_hand_l -> hand_l`，覆盖基准采样及全部静态采样帧，报告 `handHelperPairing`。位置与角度严格使用已有 `maximum_pose_position_error_cm`、`maximum_pose_rotation_error_degrees`，没有放宽阈值，也不以“成品与错误期望一致”替代辅助骨和真实手骨的配对检查。

无辅助骨的合法通用骨架明确报告 `pairCount=0`，不声称已检查这些不存在的骨；任一实际辅助骨存在却缺少对应手骨时失败，采样间辅助骨集合变化也失败。BBBC_UA 的真实输入最终验收应有三对，主执行代理必须核实 `pairCount=3`。

专项回归 `Tests/test_grip_helper_pairing.py` 覆盖静态嵌套骨链、唯一共享函数、错误期望掩盖不了实际位置及角度偏差、后续采样帧、零配对和缺目标骨。辅助骨修正不等于手掌视觉修改；工具代码摘要变化后的正式源语义及历史人工确认状态由主执行代理按真实来源处理，不能伪造新的人工 accept。

本轮针对性验证为专项七项、现有动作四项和现有静态二十五项，共三十六项通过。对现有 `Rifle02_BothHandsSavedNative.json` 的纯只读诊断检出三对，最大辅助骨位置误差约 0.006912 cm；共享函数离线同步后误差约 3.6e-15 cm，非辅助骨局部矩阵变化为零，蒙皮顶点变化约 1e-13 cm。该离线验证没有写入正式资产，不替代主执行代理后续正式保存及原生回读。

## 明确的前臂旋前与旋后

确有真实腕部残余扭转需要分配时，单条动作可声明 `forearm_roll: [{"angle_degrees": 60, "phase_frames": [20, 25, 36, 43], "twist_fraction": 0.5}]`。角度必须有限且绝对值不超过九十度，比例必须位于零至一，阶段必须有序且窗口不能重叠；不搜索角度，不自动判定自然姿势。

工作器在双骨手臂求解之后，绕实际 `lowerarm_l -> hand_l` 世界轴转前臂，重新计算腕局部变换以保持既有腕组件位置与角度。`lowerarm_twist_01_l` 的实际组件旋转取指定比例，局部反补剩余部分，不改其平移。仅明确包含此字段时输出该扭转骨轨道，MCP 写入入口同样要求通过声明校验才允许该骨。腕及扭转骨必须直接从属于实际前臂；不猜测其他骨架层次。

两个专项回归覆盖非轴对齐父骨、正负角、腕全组件变换和所有骨端点/骨长保持、半量皮肤旋转、零窗口精确保留及非法声明拒绝；连同现有动作检查共十八项通过。正式使用仍须重新原生保存回读并查看整段前臂和手部实际蒙皮，不能以腕角数值降低冒充自然姿势通过。

## 人工组件空间短路径

原始附件世界轨迹本身不正确时，可以在动作中明确声明 `left_wrist_component_keys: [{"frame": 4, "transform": [位置三项, 单位四元数四项, 单位缩放三项]}, ...]`。这些是人工选择并在正式源中保留的接触与携行姿态输入，不是搜索器输出。工作器仅在首尾关键帧之间按五次平滑位置和最短弧旋转重建左腕组件目标，仍由现有双骨手臂求解处理真实骨长和锁骨，不改变右臂。

关键帧必须为范围内严格递增整数。动作先计算枪空间接触修正及 `hand_attachment_grip_changes` 刚体反补，再由显式组件路径覆盖指定段；首尾必须匹配已经接触修正与反补后的真实目标，误差限为 `0.001` 厘米和 `0.02` 度，避免切入或退出突变；范围外目标保留。这样可保持分段持弹动作的现有边界位置并精修中段腕姿，不增加第二份源运动。回归覆盖非交换旋转、接触点、范围外保持、已反补七厘米边界保留、中段旋转覆盖和未反补旧边界拒绝；当前全部动作检查二十六项通过。真实自然性、携行避体和装入机构仍须原生回读后逐图检查。

## 明确持物指姿窗口

当原动画在持匣期间继续改变指形，导致同一附件在中间帧穿入手掌时，可声明 `finger_pose_windows: [{"hand": "hand_l", "phase_frames": [4,10,18,20], "local_rotations": {"thumb_01_l": [x,y,z,w], ...完整十五指骨...}}]`。输入是本枪实际看图确认的十五个局部单位四元数，不搜索角度或接触点。窗口按源帧有序、互不重叠并位于源动画范围；同一窗口必须完整声明一只实际手，禁止部分指骨遗漏、非单位或非有限输入。

工作器先应用显式卷曲，再按五次权重和最短弧混入固定局部指姿，满权期间不会跟随源动画漂移；原始平移、缩放、手腕和其余骨保持，后续 `finger_return_frames` 仍负责回到正式静态握姿。写入入口同样校验此制作源和十五条实际轨道。必须检查真实 Notify 显示窗口内全部帧，不能用两个关键帧的浅接触代表整段合格，也不能用固定指姿掩盖错误腕轨迹或武器机构。

固定指姿与有界阶段声明的唯一校验位于标准库模块 `BBBWeaponActionPolicy.py`，工作器和编辑器包装共同导入，完整保留明确 `boundary_hold` 的前后各一帧边界规则。编辑器包装不导入外部 NumPy 工作器；专项回归以真实 `python -S` 子进程验证无 site-packages 导入能力。

## 分段动作的边界保持

`hand_attachment_grip_changes` 和 `finger_pose_windows` 的单个窗口可明确声明 `boundary_hold: true`，使阶段最多跨出实际动作前后各一帧；满权开始和结束必须位于真实帧 `0..N-1`，阶段仍严格有序、互不重叠并使用五次平滑。未声明时继续要求阶段位于动作内部，禁止隐式负帧或末尾越界。

例：26 帧 Start 使用 `[0,4,25,26]`，12 帧 Loop 使用 `[-1,0,11,12]`，18 帧 End 使用 `[-1,0,0,16]`。Start 末帧、Loop 首尾与 End 首帧都保留同一完整腕反补和固定十五指姿，End 再正常淡出，避免分段边界把持物腕突然归零。边界保持必须提供真实帧数，拒绝更远越界、满权点不可达、非有限阶段和非布尔标记；两个必要回归与现有动作共二十三项通过。入口签名不变，实际连续性仍需原生三个分段边界回读和看图核验。
### 回读时的机构接触目标

逐帧 `verify` 的满回握目标在实际右腕及挂接变换下叠加当前声明的 `contact_translation`、`contact_transforms` 和 `hand_attachment_grip_changes`，顺序与制作输入一致。因此回握权重达到一、接槽窗口仍有效时，比较的是该帧真实制作目标；窗口退出后仍比较原静态握持目标。它仍独立比较所有写入局部轨道、未改骨与三对手部 IK。错误轨道即使与保存动画一致，也不能靠接触声明掩盖错误目标。此回读不证明最终手部自然性，仍须打开实际蒙皮视图。
