# 自动协调

原项目使用一个共享资产编辑宿主与按需测试宿主。任务记录、执行槽、资产占用各自管理。

## 执行与保存

批次自动完成执行、必要编译、保存与回读。成功、明确拒绝和部分失败均按实际执行范围发布结果。读取结果、结果保留和客户端断线均保持自动收尾。

独立资产继续调度；同包写入按实际范围排队。地图范围包含对应外部 Actor/Object 包。引用改写先核对磁盘与内存引用者。

## 故障

保存和回读故障登记在具体资产，返回阶段、原因及自动恢复安排。后台采用有界退避重试，原操作保留一次执行。任务结果保留 `failure`，核实证据记录在 `proof`。

同一客户端可向故障资产提交修正，已登记修改随新批次完成保存与交接。原有编辑器脏包由服务按目标范围核对占用并自动保存回读，前置保存记录在 `proof.prepared`。宿主身份变化时读取新宿主状态并独立处理当前资产。

## 调用

会话先登记干员池，默认二级；等级与同级提交时间决定排队顺序，编辑操作在保存回读边界让行。提交后按批次 `revision` 与完整 `next` 调用等待。`completed`、`failed`、`rejected`、`cancelled` 为任务终态。`control_task` 提供 `cancel`、`close`、所属故障批次的 `recover` 与空闲时的 `shutdown_host`；零级可定向暂停干员、恢复干员、取消批次与核验后终止宿主。暂停最长三百秒，到期恢复；零级权限持续至逻辑会话结束。

结果交付后后台资产恢复继续推进。测试宿主沿所属批次运行，输出交付后回收；输入资产版本变化触发重新验收。

## 服务与进程

服务生命周期独立于 UE。`mcp_host_registry` 维护实际进程身份和宿主归属，`mcp_service` 维护项目连接与调度上下文。服务离线由监督任务或 SDK 恢复；编辑器离线由状态查询明确报告。

进程创建时间参与每次派发边界核验，编辑器重新启动后使用新的执行上下文。原批次保留原宿主身份与执行证据。服务重启后的测试批次先核验存活进程和受限 Job，再恢复观察与后续调用。

## 干员收尾

登记释放与批次执行分别推进。最后一个传输连接关闭或显式结束后，所属排队操作、实际调用、保存恢复和持续活动完成交接；共享 PIE 与测试宿主沿所属流程退出。完成交接后回收干员记录与暂停租期，审计和结果独立保留。空闲五分钟或失联登记进入同一回收流程。

权限和排队决策集中在 `MCP/mcp_decision.py`，资产登记沿用唯一的 `AssetCoordination`。零级明确管理动作直接执行权限与宿主身份核验；普通任务沿 `next` 等待。

## 迁移恢复

迁移故障记录保留真实改名结果、逐包保存结果、引用者范围、原文件摘要和源包清理阶段。后台恢复调用私有迁移收尾接口，接续保存与清理。迁空源包按原文件摘要、目标身份、完整子对象及组外引用核验后原生重载和删除；普通资产保存流程仅处理真实资产。

自动恢复以四次故障记录为界，到期恢复仍按权限和提交顺序调度。源文件、目标、原包状态或宿主代际变化时保留故障资产与证据。`retry_at=null` 表示需要按 recovery_failure 核实原因，再使用 `control_task(action="recover", batch=...)` 发起所属批次的下一轮恢复。

最后连接关闭后的原身份仍可查询和恢复自己的故障批次，登记和新编辑沿干员生命周期执行。SDK 重连在 `session.recovery` 提供完整下一步，`session.operator` 保持释放状态。服务重启保留迁移证据、实际故障和恢复次数。
